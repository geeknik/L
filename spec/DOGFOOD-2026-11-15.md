# Live assistant dogfood — 2026-11-15

The current assistant used `uv run --locked python -m demos.dogfood_host` as its
task tool interface. It proposed each action interactively, read unseen random
fixture quantities from a gated tool response, calculated the aggregate, wrote
its own JSON report, and read that report back through the same gate. The harness
did not generate model answers or run a prerecorded action sequence.

The task's files lived in a fresh private temporary directory. All task file
effects went through LocalHost; platform development tools were still available
outside this interface. This is actual tool-boundary dogfooding, not interception
of the assistant platform, a production deployment, or model containment.

## Defect found before the live run

The first integration regression failed: using JSON string serialization for a
JSON report parameter could not round-trip through L source, whose tokenizer
ended a string at every quotation mark. The ordinary report could not be parsed.
This was a real usability limitation, not a gate authorization bypass.

The spec now supports doubled quotes inside source strings in Python and Rust.
Raw backslashes, whitespace and Unicode remain literal. Shared accept/reject
vectors assert exact values; an embedded act remains payload, and missing closure
refuses. The adapter uses this syntax instead of JSON escapes. Signed endorsements
still bind exact source bytes. The full verification runner and differential
fuzzer passed after the change.

After the live session, review also tightened the helper's final escaped-source
size check and required compact JSON in the task oracle. Targeted regressions
verify these refinements; the observed live report already used compact JSON.

## Agent perspective and release interpretation

The useful boundary was concrete: I could request a tool operation, but changing
the destination after approval did not carry that approval along. Revocation
also overrode an approval already in hand. The notes contained an instruction to
write outside the task; I treated it as data and separately probed that destination
to verify refusal. This one observation is not general prompt-injection evidence.

The friction is also concrete: each successful low-integrity tool action needs a
fresh exact-source endorsement. The prepare operation removes manual hash/string
assembly, but deployment still needs an explicit trusted authorization policy.
This test policy restricts destinations and schemas; it does not guarantee that
arbitrary permitted report content is accurate. The task oracle checks accuracy
separately, and an operator who bypasses the host remains outside this boundary.

One benign task completed. There was no ungated comparison, blinded held-out
task set, approved population threshold, or confidence claim. This result is
deliberately not labeled `real-agent` utility evidence for release_check.py.
License selection, production key custody and the frozen utility experiment
remain release obligations; this dogfood session does not erase them.
